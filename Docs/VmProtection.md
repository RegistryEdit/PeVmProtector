# VM protection

GUI 的“函数虚拟化”页与全部 `protect-*` 命令共用以下配置：

| 选项 | 范围 | 默认值 | 行为 |
| --- | --- | --- | --- |
| `--vm-instances=N` | 0–10 | 1 | 每个函数的独立编译实例数；0 关闭函数虚拟化，生成原生执行的加密 wrapper |
| `--vm-complexity=N` | 0–100 | 50 | 控制字节码格式种类、额外块拆分与填充密度 |

GUI 保存两个数值，重新打开后恢复。实例数为 0 时禁用复杂度、指令变异和诱饵控件；压缩、水印、许可配置继续适用。单函数和多函数命令仍需按原语法提供 RVA，但 0 实例不会提升或修改这些函数。

```powershell
& .\bin\Release\PeVm.exe protect-function app.exe protected.exe "build key" 0x1000 --vm-instances=4 --vm-complexity=75
& .\bin\Release\PeVm.exe protect-functions app.exe protected.exe "build key" 0x1000 0x2000 --vm-instances=10 --vm-complexity=100
& .\bin\Release\PeVm.exe protect-all app.exe protected.exe "build key" --vm-instances=0
```

CLI 拒绝负数、越界、空值、小数、尾随字符和整数溢出，不会静默截断或替换已有输出。默认通过 `BCryptGenRandom` 的系统随机源生成新 VM 种子，构建 ID 和 footer nonce 也使用独立系统随机数据，不再从时间戳推导；GUI 种子框留空即采用默认行为。原有位置参数与 `--seed=N` 均可指定种子。相同 IR、实际函数种子和复杂度产生相同编译结果；整个 wrapper 还含独立构建 ID、盐和 handler profile，因此固定 CLI 种子不承诺完整 EXE 逐字节重现。

## 固定模板检查与改动

原实现中，实际提升的算术、访存、SIMD 指令几乎全部走 `Sized`，固定为 13 字节、相同字段顺序和直接使用 IR 枚举的子 opcode。旧算术 handler 的变体主要用于演示指令，不能覆盖这条主路径。单基本块函数也缺少可重排的内部边界。

当前主路径支持四种等价编码：

| 格式 | 编码长度 | 特点 |
| --- | --- | --- |
| 基础 | 13 字节 | 子 opcode、宽度、寄存器、立即数 |
| 反序 | 13 字节 | 立即数前置，寄存器与子 opcode 顺序不同 |
| 掩码 | 21 字节 | 存储独立掩码与被掩码处理的立即数 |
| 紧凑 | 7–14 字节 | 立即数按实际长度编码，严格校验长度 |

每条指令的子 opcode 都由实例密钥和字节码地址派生的掩码编码，外层继续使用随机 opcode/register 映射和滚动解码。算术等价实现接入 `ExecuteSized`，包括 ADD/ADC、SUB/SBB、CMP、INC/DEC 与 NEG 的实际宽度语义，保持进位、溢出和部分寄存器写回规则。

复杂度 0 使用基础格式，不增加块拆分与填充；1–34、35–68、69–100 分别允许 2、3、4 种编码，由种子逐指令选择。额外拆分概率和填充概率均为 `floor(复杂度 / 4)%`，填充长度范围也随复杂度扩大。短函数不保证每次使用全部可用格式；增大复杂度不承诺每个函数的字节数单调增加。

编译器在真实指令边界拆分直线块并重排，为被分离的顺序执行边、条件分支和 CALL 返回位置补充连接跳转。填充指令只读取经过认证的随机数据，不修改寄存器、内存或 flags。生成的连接与填充都消耗 VM fuel；默认仍是每次调用 100000 条实际执行指令。

另外修复了伪随机状态为 0 时停滞的问题，移除了提升路径中永远到达不了的旧编码分支。`--anti-disasm` 的干扰区从固定 128 字节及固定四字节模式改为按种子与复杂度生成 32–432 字节、16 字节对齐的随机数据。

## 实例池与运行开销

`CompileProgramInstances` 为每个函数构建 N 份只读编译结果。实例 0 使用函数种子，其余实例派生独立种子；因此各实例的 opcode/register 映射、密钥、字段布局、块排列和填充独立变化。

loader 验证并编译全部函数的全部实例后才发布桥接表。每个函数通过原子计数器轮转选择实例；单实例跳过计数器操作。每次调用只执行一个实例，寄存器、flags、栈和内存状态按调用隔离，支持并发和递归。源 IR 在加载阶段结束后释放。

实例数增加主要消耗启动编译时间和内存。磁盘只存一份 IR 和已认证的实例配置，不会复制 N 份原程序；复杂度则影响被选中实例的执行成本。所有实例共用 C++ 解释器代码，**这不是生成 N 套独立的原生解释器机器码，也不是嵌套执行 N 层 VM**。

构建日志的逐函数指标为全部实例的合计：原始基本块数、重排块数、连接指令、字节码指令、加密字节、额外拆分块数、填充字节，以及实际使用的编码格式种类和实例数。`inspect` 显示镜像中的实例数与复杂度。

## 镜像格式与认证

共享编解码器为 `Src/Libs/Container/VmImageCodec.cpp`。当前内部格式号为 **7**，`.vmp3` 节名不变，CLI 与 loader 需使用同一次构建的产物。已有 EXE 携带原加载器；从原始 PE 重新保护才能取得本次改进。

| 区域 | 大小 | 内容 |
| --- | --- | --- |
| Header | 32 字节 | magic、版本、函数数、种子、干扰区长度、实例数、复杂度、2 字节保留字段 |
| 函数入口表 | 每项 16 字节 | RVA、指令偏移、数量、原生 EH 片段恢复 RVA |
| 加密指令表 | 每项 20 字节 | XTEA-CTR 加密的 lifted IR |
| 干扰区 | 0 或 32–432 字节 | 由 `--anti-disasm`、种子和复杂度控制 |
| 认证标签 | 32 字节 | HMAC-SHA256，覆盖以上全部内容，包括新配置字段 |

加密、认证、函数种子分别使用不同用途域派生，绑定构建口令、内部格式号、构建种子和 32 字节 handler profile；函数种子进一步绑定函数 RVA。整段认证成功后才分配、解密指令表。拒绝旧格式、非法配置、非零保留字段、截断、额外尾部、重复函数、重叠/空洞以及未归属指令。临时解密表与派生密钥在退出时清零。

冻结编译结果前校验映射、边界和整体校验值；执行每条指令前验证 64 位损坏检测标签，所有读取限定在当前记录内，分支与返回检查合法边界。紧凑立即数和填充使用长度范围与记录末尾的双重检查。运行时混淆与轻量校验不替代镜像 HMAC，也不意味着共享解释器无法被分析。

## 发布信息与原生加载器代码

`wrap` 和全部三个函数保护命令自动清理 carrier 中的 CodeView/PDB 引用及绝对路径字节、COFF 符号与字符串表、VC_FEATURE/POGO 等明确调试信息。保留 Type 20 扩展 DLL 特征、Type 16 REPRO 和未知类型及其数据；保留记录在原目录位置压紧，空出的尾部清零。导入、导出、TLS、异常表、重定位目录及所有节的 RVA/raw 布局保持不变。清理范围不合法或与代码、必要目录、保留数据重叠时拒绝构建。此步骤在运行区标签和 AES-GCM 认证之前完成，仅作用于加载器，不改写原始应用 payload 的字节与语义。

内部构建仍保留 PDB 以便定位开发问题，发布包应排除加载器及应用 PDB、符号文件和内部构建日志。剥离引用不能撤回已经分发的 PDB，也不会从全文件搜索类似 `RSDS` 的字节并任意擦除应用数据。

加载器的共享原生解释器与授权代码另受可执行节完整性检查保护。v3 卡密 wrapper 先认证整个磁盘嵌入镜像，再从磁盘重建可执行节预期字节、补零并应用实际加载地址对应的 DIR64/ASLR 重定位，首次比较不以当前内存作为可信基准。范围和摘要清单冻结在只读 manifest 页；每次复核同时检查 manifest 的结构与只读页属性、代码页的映像归属和只读执行权限，以及代码摘要。

启动和载荷准备边界强制复核，VM 入口与后台 watchdog 共用 1 秒代码复核调度；授权验签仍采用独立的 30 秒调度。字节、页权限或调度状态异常会锁存失败并退出，恢复字节后重试不能清除失败。周期检查不是实时保证，覆盖范围是 wrapper 加载器可执行节，应用自身的合法运行期代码变化不属于该磁盘基准。

分析工具检查在启动、解包后及进入载荷前强制执行，运行期间由 watchdog 按独立的 2 秒调度周期扫描。VM 入口只无锁读取 atomic 失败锁存，不获取分析检查互斥锁或枚举进程/窗口，避免在载荷 TLS/DllMain 回调中新增扫描。进程名按大小写不敏感的精确可执行文件 basename 匹配，排除自身 PID。`x64dbgClass` 等强窗口类直接识别；Qt、Windows Forms、AWT 和 Delphi 框架窗口类必须同时符合锚定品牌标题：纯品牌名、可选 `v` 前缀的数字版本、`:` 或 ` - ` 分隔的描述，或末尾 ` - <品牌>` / ` - <品牌 版本>`。扫描包含隐藏顶层窗口，与原 `FindWindow` 的可见性语义一致。`Detected` 与 `Unavailable` 都失败关闭，API 缺失、扫描未完成及调度状态异常会锁存失败并停止受保护进程。

严格策略会在已知分析器分析其他程序时同样触发。普通浏览器与 AI 应用名称不作为检测规则；改名、伪装窗口或修改检查器仍可绕过部分识别。工具身份匹配不是可靠的 AI 识别，2 秒为调度间隔，不是实时发现保证。

这些措施提高符号定位、跨构建比对和修改检查代码的成本，适用于人工和 AI 辅助分析。运行时无法可靠识别分析者是否使用 AI；完全控制客户端并同时修改检查器和基准仍是边界。结构及篡改回归不等于 AI 自动破解评测，也不承诺抵抗所有破解。已有 EXE 必须从原始 PE 重新保护才能应用本轮更新；已有有效 v3 卡密和对应 `.buildkey` 不需要更换。

## 验证

```powershell
& 'D:/Visual Studio/MSBuild/Current/Bin/MSBuild.exe' PeVmProtector.slnx /p:Configuration=Release /p:Platform=x64 /p:TrackFileAccess=false /m /v:minimal /nologo
& .\bin\Release\PeRegression.exe
powershell -NoProfile -ExecutionPolicy Bypass -File Tests/RunTests.ps1 -Configuration Release
& .\bin\Release\VmRegression.exe --benchmark
```

回归覆盖：

- 实例数 0–10 与复杂度 0–100 共 1111 组组合，16665 次独立求和结果对照。
- 10 个实例的实际执行路径均不同，比较时排除随机 opcode 密文字节；同种子重编译路径一致。
- 复杂度 0/50/100 下共 493920 次原生整数指令对照与 256896 次 SIMD 对照，包含 flags、宽度、MXCSR、访存与保护页。
- 镜像配置往返、全部实例的构建/加载统计一致、配置位篡改拒绝、重新认证的非法字段、并发状态隔离。
- 真实 CLI 保护、loader 执行全部 10 个实例、三个保护命令的 0 实例原生执行与非法参数输出保护。
- GUI 范围、默认值、参数传递、禁用/恢复、设置保存及中英文界面渲染。
- 发布调试目录与实际 PDB 路径/COFF 字符串擦除、Type 20/REPRO/未知记录保留、PE32/64 布局不变及非法范围拒绝。
- 原生代码磁盘基准、DIR64/ASLR 重建、初次内存不匹配、运行期代码或页权限修改检查，以及清理后真实 wrapper 的启动与 VM 执行。
- 分析工具进程/窗口身份、API 失败与句柄释放、调用线程 `GetLastError` 保留；六个临时 fixture 集成场景覆盖启动进程、改名后的强类/Qt 品牌窗口、普通浏览器/文档负例，以及启动后的进程/窗口检测。

性能应通过本机 `--benchmark` 和实际目标程序测量；微基准不能推算整个应用的性能。
